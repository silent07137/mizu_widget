# GIF 播放

新选择 GIF 时默认开启 2 FPS 循环播放；旧版本已有 GIF 保持静态。在组件设置中切换“GIF 播放”，或选择帧率上限：1、2、5、15、30 FPS。15 / 30 FPS 高帧率默认关闭，需要手动选择。

GIF 通过文件头识别，不要求扩展名为 `.gif`，也不依赖文件提供方正确填写 MIME 类型。选择仍通过系统文件选择器授权，原文件需要保持可读。

“允许大 GIF”默认关闭。开启后放宽源解码预算，会增加应用内存占用，解码失败仍显示静态图片。设置按组件保存，用户图片不上传。

播放偏好默认为“画质优先”：尽量保留至少 75% 的输出边长，预算不足时优先减少采样帧；预览显示实际 FPS。“帧率优先”沿用时间采样策略，预算不足时会缩小画面。极小屏幕或很大的组件仍可能继续缩小；选择 30 FPS 不保证桌面能以原始清晰度达到 30 FPS。

## 显示方式

平台 Movie 根据时间解码采样帧，应用在配置保存、尺寸变化或系统更新时发布一次 RemoteViews。桌面的系统 ViewFlipper 负责循环显示，应用没有后台逐帧刷新循环、常驻服务或闹钟。

这是受限的时间采样播放，无法保证原动画的逐帧时序和原始清晰度，也不保留文件中的有限循环次数。播放按所选 FPS 上限量化，整轮时长可能延长。透明区域、帧清理、缩放、圆角、不透明度和背景参与每个输出帧渲染。

预览在应用不可见时暂停；桌面宿主窗口不可见或控件脱离窗口时，系统 ViewFlipper 会停止计时。其他桌面的页面缓存、可见性及计时策略可能不同。

Android 15 及以上通过系统“强制停止”应用时，系统会暂时禁用该应用的所有组件；重新打开应用后恢复。这与普通后台进程回收不同，详见 [Android 官方说明](https://developer.android.com/about/versions/15/behavior-changes-all#widgets-disabled)。

## 上限与回退

| 项目 | 默认 | 允许大 GIF |
| --- | --- | --- |
| 源文件 | 8 MiB | 32 MiB |
| 源画布 | 2097152 像素 | 4194304 像素 |
| 源帧数 | 128 | 512 |
| 画布像素 × 源帧数 | 16777216 | 67108864 |
| 单轮源时长 | 120 秒 | 300 秒 |
| 普通模式采样帧 | 24 | 24 |
| 高帧率采样帧 | 120 | 120 |
| 所有输出帧合计 | 最多 2097152 像素，ARGB 位图约 8 MiB | 相同 |

源解码预算与输出预算分别检查。输出预算取 8 MiB 与 1.25 屏 ARGB 像素中的较小值，为桌面的系统限额留出余量；大 GIF 开关不绕过桌面限制。应用峰值内存还包括压缩数据和平台解码器，因此仍保留最终源上限。所有帧一起满足总预算，长动画或画质优先可能降低实际帧率，预览显示“已降帧”。

只有一帧、超出源上限、损坏或平台解码失败的 GIF 回退静态预览，设置页会提示“GIF 无法播放或超限 · 静态预览”。静态帧也无法读取时显示重新选择入口。

## 自制测试图

仓库只包含自制测试图的生成代码，不包含用户 GIF。

```sh
python3 tools/make_gif_fixture.py /tmp/mizu-test.gif
python3 tools/make_gif_fixture.py /tmp/mizu-alpha.gif --transparent
```

这些合成图用于颜色换帧、透明区域与清除旧帧验证。完整测试列表见 [TESTING.md](TESTING.md)。
